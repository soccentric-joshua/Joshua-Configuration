## P0 — Build is broken out of the box (blockers)

### C1. Commit the vendored crate sources (`vendor/`)
- **Symptom:** `cargo build` fails immediately:
  `failed to read root of directory source: .../vendor — No such file or directory`.
- **Cause:** `.cargo/config.toml` replaces `crates-io` with
  `[source.vendored-sources] directory = "vendor"`, and `.github/workflows/ci.yml`
  sets `CARGO_NET_OFFLINE: true`. There is no `vendor/` in the repo, so no
  dependency can be resolved anywhere (local or CI).
- **Fix:** run `make vendor` (regenerates `vendor/` from the local cargo cache;
  verified offline-capable here — 284 MB, ~370 crates) and commit the directory.
  Without committing it, a fresh CI checkout has nothing to build against.

### C2. Remove the `.gitignore` rule that ignores `vendor/`
- Line 27 of `.gitignore` is an uncommented `vendor/`, which ignores the vendored
  sources. This directly contradicts the comment on line 9 ("Vendored crates are
  regenerated by `make vendor` and **intentionally committed** for offline
  reproducible builds").
- Verified: `git check-ignore vendor` → returns `vendor`.
- **Fix:** delete the trailing `vendor/` line (keep the commented `# /vendor`
  for those who want to ignore it locally). Must ship in the same commit as C1,
  or CI stays broken.

## P1 — CI correctness

### C3. Align the CI Rust toolchain version
- `.github/workflows/ci.yml` pins `dtolnay/rust-toolchain@1.75.0` (only `rustfmt,
  clippy`).
- `rust-toolchain.toml` pins **1.97.1**, and `Cargo.toml` declares
  `rust-version = "1.85"`. Transitive crates in the lockfile (e.g. `idna_adapter`,
  `indexmap`) require edition2024 / Rust 1.85+, so a 1.75.0 CI build **will fail**.
- This mismatch is explicitly flagged as unresolved in `.claude/CLAUDE.md`.
- **Fix:** pin CI to **1.97.1** (add `targets` in the same action for the
  cross-build job), establishing 1.97.1 as authoritative. Local `cargo` is 1.97.1;
  build/test/lint/validate all pass on it.

### C4. CI cross-build matrix omits `x86_64`
- Spec §6 / `Makefile::cross` requires all **three** cross-targets:
  `x86_64-unknown-linux-gnu`, `aarch64-unknown-linux-gnu`,
  `armv7-unknown-linux-gnueabihf`.
- CI `cross-build` matrix lists only `aarch64` and `armv7`. The `host-test` job
  runs `make build` (a debug host build), not `--release --target x86_64`, so the
  x86_64 cross artifact is never validated.
- **Fix:** add `x86_64-unknown-linux-gnu` to the matrix (no extra linker). Ensure
  the aarch64/armv7 linkers (`gcc-aarch64-linux-gnu`, `gcc-arm-linux-gnueabihf`)
  are installed wherever a cross build runs.
